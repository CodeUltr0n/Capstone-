SLIDE 3 — Introduction: Project Overview
  • Open Standard Foundation: MCP-Orchestrator is an open, centralized, lightweight orchestration middleware built directly atop the Anthropic Model Context Protocol (MCP) standard (Nov 2024 / updated to stateless 2026-07-28 specification).
  • The Core Paradigm Shift: Replaces brittle, isolated agent silos with a single context-aware control plane:
    • Captures Multi-Modal Context: Natural language intent + environmental vector (clock, GPS coordinates, urgency, user history).
    • Deterministic Pre-Scoring: Computes a transparent Context-Aware Utility Score for every registered tool before contacting the LLM.
    • Top-K Tool Pruning: Prunes low-scoring schemas, assembling an ultra-compact prompt.
    • Multi-Transport Execution: Dispatches selected tasks across heterogeneous MCP nodes via Stdio, SSE, or HTTP JSON-RPC.
  • Dual-Engine Persistence: Supports zero-configuration local SQLite (WAL mode) and managed cloud PostgreSQL, backed by local in-memory fallback.
SLIDE 4 — Introduction: Problem Statement & Motivations

Problem Statement

  • Context Siloing & Zero Shared Memory: Independent agent bots maintain separate conversational memories; cross-service scheduling without expensive prompt synchronization is impossible.
  • Combinatorial Token Bloat: Dumping all tool schemas into the system prompt exhausts context windows quadratically ($O(N)$ growth), driving up latency and cloud costs.
  • Absence of Real-World Environmental Awareness: Conventional agents operate blindly to physical real-world signals (temporal operating hours, physical courier distance, emergency urgency).

Industry Motivations

  • Standardization: By late 2026, MCP is the universal open standard adopted across Claude, ChatGPT, GitHub Copilot, and cloud gateways (AWS MCP Gateway, Cloudflare MCP v2).
  • Cost & Latency Mandate: Token reduction (≥ 40%) and sub-25 ms scheduling latency are measurable, defensible KPIs.
  • Reliability: Deterministic graceful degradation during API/DB outages is an enterprise requirement.
SLIDE 5 — Introduction: Objectives & Expected Impact

Core Objectives

  • Architect a modular, decoupled orchestration middleware (intent parsing, heuristic scoring, transport dispatch, state storage).
  • Formulate a transparent multi-factor utility scoring equation (Urgency, Distance, Time-of-day, User Affinity).
  • Build an open/closed plugin registry connecting new MCP services with <15 lines of config.
  • Establish a 3-tier Graceful Degradation FSM (Full LLM → Deterministic Degraded → Survival edge mode).
  • Achieve measurable KPIs: ≥40% token reduction, sub-25 ms overhead, ≥90% accuracy, ≥80% coverage.

Expected Impact

  • 40-60% Token Savings: Immediate cost savings on commercial LLM inference.
  • Sub-25 ms Scheduling: High-throughput, real-time dispatch suitable for edge and mobile clients.
  • Pluggable Architecture: Drop-in compatibility with the wider Anthropic MCP ecosystem.

SLIDE 10 — Proposed Solution: Algorithms & Technologies

Core Scoring Equation

Score(Task) = w1·Urgency + w2·SpatialProximity + w3·TemporalRelevance + w4·UserAffinity

Default weights (externalized in YAML):
  w1 = 0.35  (Urgency)
  w2 = 0.25  (Spatial Proximity)
  w3 = 0.20  (Temporal Relevance)
  w4 = 0.20  (User Affinity)

3-Tier Graceful Degradation FSM

  • State 1 (FULL): LLM ✓, DB ✓ → Full generative LLM function calling with cloud audit.
  • State 2 (DEGRADED): LLM ✗, DB ✓ → Deterministic top-ranked tool dispatch; 100% request survival.
  • State 3 (SURVIVAL): LLM ✗, DB ✗ → Time-layer heuristic dispatch from local in-memory seed cache.

SLIDE 14 — Summary: Key Findings, Limitations, Future Directions

Key Findings

  • Token Reduction Exceeded Target: Achieved 44.6% token reduction over LLM-only baseline (exceeding ≥40% target).
  • Sub-25 ms Latency: Prioritization completes in 17 ms on average (well under 25 ms ceiling).
  • High Accuracy Maintained: 91.5% decision accuracy—within 2% of brute-force LLM inference at 1/40th pre-routing latency.
  • 100% Uptime Under Failures: Three-tier degradation FSM validated across simulated LLM and database outages.
  • Open/Closed Plugin Extensibility: New server modules plug in with <15 lines of declarative configuration.

System Boundaries & Limitations

  • Synthetic Context Constraints: Current context signals are test vectors; commercial deployment requires hardware sensor integration.
  • Static Heuristic Weights: Weights are currently set empirically; automated self-tuning via reinforcement learning is open for future work.
  • Single-Node Orchestration: Distributed cross-orchestrator consensus has not yet been evaluated.

Future Horizons

  • Federated discovery integration with the Official Anthropic MCP Registry & AWS MCP Gateway.
  • Dynamic weight adaptation via Multi-Armed Bandits (MAB) or online RLHF.
  • Extension to Agent-to-Agent (A2A) protocol for decentralized autonomous swarms.
  • Publication of reference implementation at a national AI/cloud systems conference.
